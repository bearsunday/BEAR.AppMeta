## Project Overview

BEAR.AppMeta is a lightweight PHP library that manages application metadata for BEAR.Sunday applications. It provides access to application directory paths (appDir, logDir, tmpDir) and generates metadata for application resources.

## Core Architecture

### Main Classes

- **Meta** (`src/Meta.php`): The primary entry point. Accepts an application name (Vendor\Project format), optional context (e.g., 'prod-hal-app'), and optional appDir. Reports where the application writes; it creates nothing.

- **AbstractAppMeta** (`src/AbstractAppMeta.php`): Base class containing:
  - `getResourceListGenerator()`: Returns a generator yielding [class, file] pairs for all ResourceObject classes
  - `getGenerator(string $scheme)`: Returns ResMeta objects for resources. Accepts 'app', 'page', or '*' as the scheme parameter

- **ResMeta** (`src/ResMeta.php`): Value object containing resource metadata (uriPath, class, filePath)

### Key Behaviors

- The `Meta` constructor determines appDir by reflecting on `{AppName}\Module\AppModule` class location
- URI paths are generated by converting class names from CamelCase to kebab-case
- When scheme is '*', generates full URIs like `app://self/one`
- When scheme is specific (e.g., 'app'), generates relative URIs like `/one`

## Type Safety and Domain Types

This codebase uses Psalm domain types extensively for enhanced type safety:

- **`non-empty-string`**: Used for application names, directory paths, URIs, and file paths that must never be empty
- **`class-string<ResourceObject>`**: Used for resource class names to ensure they extend ResourceObject
- **`@param-out`**: Used in `camel2kebab()` to specify the output type of reference parameters
- **`array<non-empty-string>`**: Used for arrays of non-empty strings like namespace path segments

### Key Type Annotations

- All directory properties (`$name`, `$appDir`, `$tmpDir`, `$logDir`) are typed as `non-empty-string`
- Generator return types specify exact tuple shapes: `Generator<array{0: class-string<ResourceObject>, 1: non-empty-string}>`
- ResMeta constructor parameters and properties all use strict domain types

When adding new functionality, maintain this level of type safety by:
1. Using `non-empty-string` for strings that should never be empty
2. Using `class-string<T>` for fully qualified class names
3. Adding both standard `@param`/`@return` and `@psalm-param`/`@psalm-return` annotations
4. Running `composer sa` to verify type safety with both PHPStan and Psalm
